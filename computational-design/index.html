Computational Design

Parametric models that preserve intent.

Controllable geometry, readable parameters, and predictable behavior. Grounded in traditional architectural practice, then made repeatable and documented.

Constraint-first

Define what must hold true before form takes shape.

Setbacks, spans, code minimums, and program limits enter the model first.

Geometry is generated inside those boundaries, not the other way around.

Editable geometry

Change a parameter, not the whole model.

Walls, roofs, and assemblies update from a single rule set.

Edits stay local so design intent survives every revision.

Rationalization

Intent is resolved into clean, buildable rules.

Complex surfaces become panels, beams, and repeatable units.

The result stays legible to fabricators, estimators, and reviewers.

Documentation

Decisions stay traceable and recorded.

Parameters, assumptions, and outputs are versioned alongside the model.

Hand-off includes what changed, why, and what still needs review.

Architecture foundations

Previews that show the work is grounded in core practice, not only generation.

code / regulation / programming · Design

Iterative design Theory

Site, program, and concept are encoded as parameters before form is drawn.

Code and regulation enter the model as constraints, not after-the-fact checks.

Each iteration preserves intent so alternatives stay comparable and documented.

junction / tolerance / constructability · Detailing

Iterative detailing Strength

Junctions, offsets, and material transitions are modeled to survive fabrication and install.

Tolerances and assembly order are built into the system, not left to the field.

Detail sheets stay tied to the parent model when geometry changes.

zoning / planning / green design · Rules

Practical practice Rules

Zoning, planning overlays, and building code set the feasible envelope first.

Green-design thresholds act as design drivers alongside massing and program.

Assumptions are versioned and handed off with the drawings for review.

Headed workflow (non‑negotiable)

AI can assist drafting, debugging, and documentation — but production stays verifiable inside Rhino/Revit.

Where AI helps

  • Structure intent into parameters + constraints
  • Generate/debug code
  • Write documentation and checklists

Where verification happens

  • Rhino/Grasshopper or Revit/Dynamo
  • Deterministic scripts
  • Human review pass + standards
